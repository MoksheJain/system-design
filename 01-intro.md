## What is System Design?
System design is a process of defining the architecture, components, modules, and data flow of a system to satisfy a set of requirements. It basically covers how data flows through the system, how various components of an application talk to each other and whole thing holds itself up when the load on the server is enormous. 

## When to use system design?
Before implementing the whole system. Check for tradeoffs, plan before writing code. Talk of things like cost, performance, scalability before writing code and not leaving it to be an exponential burden after the system is built.

## How to approach system design?
Clarify requirements, yeah. As easy as it sounds, clarify requirements, of what the system is going to do, what users does it serve and what scale is must handle. From there, design moves through estimating capacity, and then sketching a high level architecture before drilling down into individual components like databases, load balancers and caches.

It is an iterative process. No design can fit all of the constraints at once. Design must be updated and trade-offs must be revisited as the scale of the project changes. 

## How to answer a system design question?
Interviewers will often ask to design a feature in an already built app like Facebook, Twitter, etc. Of course, these systems were built by engineers over years and not in a 30 minute interview.
